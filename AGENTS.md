# Agent Guidelines & Repository Architecture for home-settings

This repository provides automated workstation provisioning, dotfiles, shell environments, and developer toolchains for **modern Unix systems: Debian-based Linux (Ubuntu, Debian, Pop!_OS), RHEL-based Linux (Fedora, RHEL, CentOS Stream, Rocky Linux), and macOS**.

Any AI agent interacting with or modifying this repository **MUST** strictly adhere to the instructions and invariants below.

---

## 1. Non-Negotiable Core Invariants & Guardrails

| Rule | Invariant | Description |
| :--- | :--- | :--- |
| 🚫 **NEVER** | **No Hardcoded Personal Paths** | Never commit paths containing personal usernames like `/home/brianb/`, `/Users/username/`, or Windows user profiles. Always use `$HOME`, `${XDG_DATA_HOME:-$HOME/.local/share}`, `${XDG_CONFIG_HOME:-$HOME/.config}`, or `${XDG_CACHE_HOME:-$HOME/.cache}`. |
| 🚫 **NEVER** | **No Blind Error Suppression** | Never redirect `stderr` to `/dev/null` or use blanket quiet flags (`MISE_QUIET=1`, etc.) in startup files (`.zshrc-addendum`, `.bashrc-addendum`) or orchestrators. Always resolve the root cause (e.g. trusting configs, installing missing toolchains). |
| 🚫 **NEVER** | **No Default Heavy Daemons / GUI Apps** | Heavyweight database server daemons (PostgreSQL, MariaDB) and GUI applications (Chrome, VS Code) must **never** be installed by default. Only lightweight client CLI tools (`psql`, `mariadb-client`) are installed unless opted into via `--with-postgres`, `--with-mariadb`, `--db <engine>`, or `--with-gui`. |
| 🚫 **NEVER** | **No Hardcoded Dotfile Arrays in Setup** | Never maintain hardcoded lists of dotfile paths in `setup.sh`. All dotfiles must be auto-discovered declaratively by `modules/10-dotfiles.sh` and mirrored to `$HOME`. |
| 🚫 **NEVER** | **No Redundant Standard Git Aliases** | Standard Git aliases (`ga`, `gst`, `gco`, `gd`, `gb`, `gl`, `gp`) are provided directly by Oh-My-Zsh's `git` plugin. Keep `.aliases` pruned to custom workflows (`gcommit`, `gamend`, `gsync`, `guser-branch`, `gprune`, `gpurge`, etc.). |
| 🚫 **NEVER** | **No Starship Prompt** | The shell prompt is strictly single-line **Powerlevel10k Solarized Dark**. Never re-introduce `starship`. |
| 🚫 **NEVER** | **No EOL Java Releases** | Only actively supported Java LTS releases are allowed (**Java 17 LTS**, **Java 21 LTS**, **Java 25 LTS**). Deprecated/EOL versions (Java 8, Java 11) must never be used. Runtimes are managed declaratively via `.mise.toml` (`java = "lts"`). |
| 🚫 **NEVER** | **No Nested Directory Symlinks** | When symlinking directory trees (e.g. `${XDG_CONFIG_HOME:-$HOME/.config}/nvim`), always check if the target is an existing physical directory. If so, back it up (`nvim.bak.<timestamp>`) before calling `ln -sfn` to prevent creating nested links (`~/.config/nvim/nvim`). Enforced via `lib/symlink.sh`. |
| 🚫 **NEVER** | **No Chromatic Noise on Scope Qualifiers** | Never color prefix qualifiers (`std::`, `boost::`, `context.`, `fmt.`) in accent colors. Only formal declaration sites (`package main`, `namespace core::telemetry`, `using namespace ...`) receive Violet (`#6C71C4`); qualifiers in code strictly remain in calm Base0 Grey (`#839496`). |
| 🚫 **NEVER** | **No Semantic Flipping for Factory Functions** | Never color factory function calls (`NewClusterNode`, `NewService`) in Yellow as constructors. In languages like Go where constructors are standard functions, function invocations strictly remain in calm Base0 Grey (`#839496`) alongside all routine invocations. |
| 🚫 **NEVER** | **No Token Fracturing in Structured Strings or Attributes** | Never fracture compound constructs like Go struct tags (``` `json:"port"` ```), C++ attributes (`[[nodiscard]]`), Rust attributes (`#[derive]`, `#[inline]`), printf format specifiers (`%s\n`), diff lines (`+ line`), or Rust lifetimes (`'a`, `'static`) into multi-colored checkerboards. They must remain unified in their primary accent. |
| 🚫 **NEVER** | **No Piped Multi-Kilobyte Variables to Early-Terminating Consumers** | Under `set -euo pipefail`, piping multi-kilobyte strings into early-terminating consumers (e.g. `echo "$OUT" \| grep -q`) triggers `SIGPIPE` (exit 141) on the producer. Always use Bash here-strings (`grep -Fq "$pattern" <<< "$OUT"`) or temporary files to ensure 100% deterministic test execution. |
| 🚫 **NEVER** | **No Yellow in Markdown Headings** | Never use Solarized Yellow (`#B58900`) for Markdown headings. Headings strictly follow Semantic Architecture: H1 Orange (`#CB4B16`), H2 Blue (`#268BD2`), H3 Violet (`#6C71C4`), H4 Base1 (`#93A1A1`), H5/H6 Base0 (`#839496`), with `#` delimiter sigils in Base01 (`#586E75`). Yellow is reserved exclusively for control flow / execution pathways inside embedded code blocks. |
| 🚫 **NEVER** | **No Artificial Bold Typography in Headings** | Never apply bold font styles across Markdown headings (`bold = false`). Monospace character metrics and zero-jitter layout are strictly preserved. Explicit author bold (`**bold**`) remains Base1 Bold (`#93A1A1`). |
| 🚫 **NEVER** | **No High-Contrast Static Prompt Icons** | The shell prompt OS icon must never be rendered in high-luminance colors (Base2 `#EEE8D5` or Base1 `#93A1A1`) that outshine actionable semantic landmarks like the current directory path (Blue `#268BD2`) or Git branch status (Green/Yellow). It strictly remains in calm Base0 (`#839496`). |
| 🚫 **NEVER** | **No Perpendicular Box-Drawing Shelf Separators** | Subsegment separators within the prompt shelf must use thin directional chevrons (`\uE0B1` on left, `\uE0B3` on right), never full-height box-drawing bars (`│`), to eliminate visual grid cages and shell pipe (`\|`) ambiguity while preserving kinetic horizontal momentum. |
| 🚫 **NEVER** | **No Asymmetrical Right Prompt Margin Gap** | Never allow Zsh's default 1-space padding to detach the right prompt from the screen margin. Right prompt must remain flush against the right edge via `ZLE_RPROMPT_INDENT=0` configured after prompt expansion, matching the flush left prompt margin (`POWERLEVEL9K_LEFT_PROMPT_FIRST_SEGMENT_START_SYMBOL=''`). |
| 🚫 **NEVER** | **No Cross-Domain Collisions in Filesystem Tools** | In `LS_COLORS` and `EZA_COLORS`, never assign directory Blue (`#268BD2`) or archive Orange (`#CB4B16`) to cryptographic keys and certificates (`.key`, `.pem`, `cr`). Cryptographic credentials strictly belong to Magenta (`#D33682`), isolated from general navigation. |
| 🚫 **NEVER** | **No Uncalibrated ANSI Slot Assumptions** | In terminal profiles with custom 16-color palettes, never assume basic ANSI 33 is Orange or ANSI 35 is Violet. Tools emitting basic ANSI codes (`dircolors`) must be calibrated to the terminal emulator's concrete slot mapping (e.g. Ghostty slot 9 / ANSI `91` for Orange, slot 13 / ANSI `95` for Violet). |
| 🚫 **NEVER** | **No Greedy Computed Member Captures** | Computed member keys (`[expr]`) must never be captured greedily as routine declarations in Blue (`#268BD2`). Brackets `[` and `]` delimit an arbitrary runtime expression evaluation plane whose inner tokens remain on their native semantic tiers (Base0 Grey `#839496` for identifiers). |
| 🚫 **NEVER** | **No Unbounded Contextual Keyword Trapping** | Contextual keywords (`of`, `in`, `catch`, `finally`) must never be matched without surrounding syntactic guards. Always use negative lookbehinds `(?<!\.)` to prevent method invocations (`Array.of()`) and negative lookaheads `(?!\s*:)` to prevent object property labels (`{ of: 1 }`) from falsely masquerading as Yellow control flow. |
| 🚫 **NEVER** | **No Transparent Capture Fallthrough for Canvas Neutralization** | Never rely on `@none` (which has `fg = nil`) to reset an upstream-highlighted token to Base0 Grey. In Neovim's extmarks renderer, attributes cascade across capture stacks, allowing underlying colors (like `@markup.raw` Cyan) to show through. Always map to a concrete capture with an explicit Base0 Grey binding (`@markup.raw.block`, `@variable`) and reinforce with language-scoped overrides (`@markup.raw.xml`). |
| 🚫 **NEVER** | **No Unconditional Language Injections** | Never inject child languages based solely on generic container names (`<script>`) without explicit attribute qualifiers (`type="text/javascript"`). Blind injections bypass the host grammar, break non-matching payload scripts (shell scripts, SQL), and lock tokens inside an incompatible foreign AST. |
| 🚫 **NEVER** | **No Rogue OSC 8 Hyperlink Metadata** | Never allow Tree-sitter queries to emit `(#set! @capture url ...)` directives that attach `metadata.url` to extmarks. In modern terminals (Ghostty, GNOME Terminal), this causes Neovim's TUI to emit OSC 8 terminal escape sequences, turning URLs into clickable hyperlinks. Upstream queries containing `url` metadata must be superseded at the base query level (`queries/<lang>/highlights.scm` without `;; extends`), because `after/queries/` cannot suppress metadata collected by `iter_matches`. |
| 🚫 **NEVER** | **No Diagnostic Foreground Mutation of Syntax** | Never set `fg` on `DiagnosticUnderline*` groups (`Error`, `Warn`, `Info`, `Hint`). Always set `fg = "NONE"` alongside `sp` and `undercurl/underline`. Diagnostic squiggles indicate diagnostic severity strictly through underline color (`sp`), leaving the underlying token's syntax highlighting completely uncorrupted (preventing URLs or strings from turning yellow/red). |
| 🚫 **NEVER** | **No Rogue Document Link Providers** | In Neovim LSP configs, always nullify `client.server_capabilities.documentLinkProvider = nil` in `LspAttach`. Document link providers attach hyperlink extmarks that turn string URLs into clickable OSC 8 links and interfere with syntax highlight colors. |
| 🚫 **NEVER** | **No Remote Schema LSP Validation for Sample Code** | Never enable remote schema downloading or validation in language servers (`jsonls.settings.json.validate = { enable = false }`, `yamlls.settings.yaml.validate = false`). Remote schema lookups on mock/sample URIs (e.g. `https://api.example.com/...`) trigger DNS resolution failures and spurious diagnostic warnings. |
| 🚫 **NEVER** | **No Yellow in Declarative Data, Config, or Stylesheet Documents** | Never use Solarized Yellow (`#B58900`) in JSON, YAML, TOML, XML, HTML, CSS, or Java Properties documents. Control flow Yellow is reserved strictly for imperative execution pathways (`if`, `return`, `for`, `switch`, `match`). CSS properties and configuration keys strictly belong to Solarized Green (`#859900`), and custom property identifiers / variable calls strictly remain in calm Base0 Grey (`#839496`). |
| 🚫 **NEVER** | **No Fracturing or False Declaration of Interpolated Keys** | In property files and templated configurations, never color variable interpolation keys (`${key}`) in Green as if they were property declarations. Interpolation wrappers (`${`, `}`) and referenced keys strictly remain in calm Base0 Grey (`#839496`). |
| 🚫 **NEVER** | **No Flat Structural Hierarchy in TOML** | Never color TOML table section headers (`[table]`, `[[array]]`) in the same color as mapping keys (`key =`). Table headers strictly belong to Solarized Blue (`#268BD2`) as macro-level section boundaries, and mapping keys belong to Solarized Green (`#859900`). |
| 🚫 **NEVER** | **No String Escapes for Temporal Literals** | Never capture unquoted TOML date-times (`2025-09-14T08:30:00Z`) as `@string.special` (Cyan). Unquoted temporal scalars strictly belong to Solarized Magenta (`#D33682`) alongside numbers and booleans. |
| 🚫 **NEVER** | **No Fracturing of CSS Custom Properties or Compound Keywords** | Never permit token fracturing of custom property identifiers (`--color-base03`, `--bg-primary`) or compound sizing keywords (`auto-fill`, `auto-fit`, `inline-block`, `ease-in-out`) into pseudo-numbers, disjoint prefixes, or dangling operators. They must be captured atomically in calm Base0 Grey (`#839496`). |
| 🚫 **NEVER** | **No Token Fracturing in Hex Colors or Prefixed Literals** | Never separate the `#` in hex colors (`#002b36`) as a delimiter or operator. The leading `#` is an atomic literal prefix in Solarized Magenta (`#D33682`). ID selectors (`#dashboard-grid`) strictly belong to Solarized Blue (`#268BD2`), completely isolated from numeric color literals. |
| 🚫 **NEVER** | **No Catch-All Selector Priority Swallowing in Tree-sitter** | Broad structural selector captures (such as `((selectors) @type (#set! "priority" 125))`) must never swallow leaf tokens. Attribute string values (`"healthy"` in `[data-status="healthy"]`), nesting parent combinators (`&`), attribute names (`data-status`), and custom properties must be shielded with priority `>= 130`. |
| 🚫 **NEVER** | **No Dual-Redundant Tree-sitter Query Sets** | Never maintain duplicate query definitions across `queries/<lang>/` (base supersedure) and `after/queries/<lang>/` (runtime extensions). Use `after/queries/` with `;; extends` strictly for additive extensions to upstream distro queries; use `queries/` without `;; extends` when fully superseding upstream queries (e.g. eliminating rogue metadata or broad selector swallowing). Never define both for the same language. |
| 🚫 **NEVER** | **No Inverted Rule Ordering for Catch-All Fallbacks** | In Tree-sitter query architecture, generic catch-all patterns (such as `(value) @string`) must always precede specialized predicate rules (`((value) @number (#lua-match? ...))`). Placing catch-alls after specialized rules in document order causes the fallback to overwrite specific syntax captures. |
| 🚫 **NEVER** | **No Unpinned Degradation of Modern Syntax Standards** | Never permit modern language features (such as CSS Container Queries Level 3 with named container statements `@container name (...)`) to collapse into unhighlighted `ERROR` nodes due to outdated distro-packaged parsers. Upstream Tree-sitter revisions must be declaratively pinned (`parsers.<lang>.install_info.revision`) inside a `User` `TSUpdate` autocmd so `nvim-treesitter`'s `reload_parsers()` cannot wipe the pin. |
| 🚫 **NEVER** | **No Chromatic Noise in Editor Framing & Navigation Chrome** | Non-code UI chrome (line numbers, split borders, float borders, gutter columns) must never use bright accent colors that compete with code semantics. Line numbers follow the monochromatic luminance scale (Base01 inactive, Base1 active on Base02), and window borders strictly remain in Base01. |
| 🚫 **NEVER** | **No Frozen `gitstatusd` / `libgit2` Prompt Daemon** | Never enable `gitstatusd` (`POWERLEVEL9K_DISABLE_GITSTATUS=true` must remain set in `.p10k.zsh`). The 2022 `gitstatusd` (`libgit2`) binary fails on modern Git `reftable` (`extensions.refstorage = reftable`) and SHA-256 repositories. VCS segments in both Zsh (`_p9k_solarized_prompt_vcs`) and Bash (`_solarized_bash_prompt`) must use single-fork `git --no-optional-locks status --porcelain=v2 --branch` and zero-fork `.git/config` remote host icon resolution (``, ``, ``, ``). |
| 🚫 **NEVER** | **No In-Place File Unlinking under Daemon Emulators** | Never delete or unlink active font files in-place with raw `rm -f "$target"` while terminal servers (`gnome-terminal-server`) are active. Always download to atomic temporary files (`$cached.tmp.$$.$BASHPID`) and install via atomic `mv -f` to preserve open inodes and prevent tofu missing glyphs. Always provision official `ryanoasis/nerd-fonts` v3.3.0+ `MesloLGS Nerd Font Mono` (`MesloLGSNFM-Regular`), maintain the `10-meslo-nerd-font.conf` fontconfig alias mapping legacy `MesloLGS NF` to `MesloLGS Nerd Font Mono`, and configure terminal emulators directly to `MesloLGS Nerd Font Mono 12` (`MesloLGSNFM-Regular` on macOS). |
| ✅ **ALWAYS** | **Zero-Dependency Portable `.vimrc` & `.bashrc-addendum` Parity** | `dotfiles/.vimrc` and `dotfiles/.bashrc-addendum` must remain self-contained so copying just those two files to a restricted remote server provides the inline Solarized Dark TrueColor + `cterm` Vim palette (`s:ApplySolarizedDark()`) and the `Base02` (`#073642`) shelf Bash prompt (`_solarized_bash_prompt()`) with remote VCS icons, `LS_COLORS`, `LESS_TERMCAP_*`, and core Git workflow aliases. |
| ✅ **ALWAYS** | **Modular Stage Architecture** | Keep `setup.sh` strictly as an orchestrator CLI (~240 lines). Subsystem provisioning belongs in dedicated scripts under `modules/<NN>-<name>.sh` using shared helpers in `lib/`. |
| ✅ **ALWAYS** | **LTS Preference for Mise Tools** | For all tools defined in `.mise.toml`, specify `lts` whenever supported by the tool's ecosystem (`java = "lts"`, `node = "lts"`). For tools without an official LTS channel (Go, Python, Maven, Terraform, Rust, Neovim), default to `latest` stable. |
| ✅ **ALWAYS** | **Modern Neovim via Mise** | Modern Neovim (0.11+ / 0.12+) is provisioned via `mise` (`neovim = "latest"`), avoiding obsolete distro packages (such as Ubuntu's default 0.9.5). |
| ✅ **ALWAYS** | **XDG Base Directory Compliance** | Keep `$HOME` clean of language runtime workspaces and cache clutter. Go workspace and cache must strictly point to XDG paths: `export GOPATH="${XDG_DATA_HOME:-$HOME/.local/share}/go"` and `export GOCACHE="${XDG_CACHE_HOME:-$HOME/.cache}/go-build"`. |
| ✅ **ALWAYS** | **Idempotent & Fail-Fast Scripts** | All Bash scripts must begin with `set -euo pipefail`. Re-running `setup.sh` or `Makefile` targets must be completely safe, non-destructive, and produce identical results. |

### Universal Semantic Color Contract
Colors across our developer workstation fulfill invariant domain roles across all languages and filetypes:

| Palette Color | Hex Code | Universal Semantic Role | Manifestations Across Languages & Tools |
| :--- | :--- | :--- | :--- |

2. **Pillar II: Operational Role Invariance (Runtime Semantics over Static Syntax)**
   - *Core Premise*: Highlighting must reflect the runtime operational role of a token rather than its static lexical spelling or compiler internal representation:
     - **Definition vs. Invocation Decoupling**: Function declarations (`func Process()`) are structural landmarks in Blue (`#268BD2`); function and method invocations (`node.Process()`) are runtime operations resting on the calm Base0 Grey (`#839496`) canvas.
     - **Factory Invariance (No Semantic Flipping)**: In languages where constructors are ordinary functions (such as Go `NewClusterNode` or factory patterns), constructors remain invocations in calm Base0 Grey (`#839496`), preserving visual continuity across all call sites rather than falsely masquerading in Yellow as language-level primitive constructors.
     - **Built-in Routine Invariance**: Standard library and compiler built-in routines (`panic(...)`, `make(...)`, `len(...)`, `printf(...)`) function identically to user routines at the call site and sit calmly on Base0 Grey.
     - **Dual-Identity Contextual Disambiguation**: In Java, C++, and Python, receiver keywords fulfill dual functions based on syntax context: when acting as an instance reference or receiver (`this.timeoutMs`, `self.val`, `super.init()`), they represent immutable instance constants in Solarized Magenta (`#D33682`); when acting as explicit constructor delegations (`this(...)`, `super(...)`), they act as callable routine invocations in calm Base0 Grey (`#839496`).
     - **Computed Member Key Invariance (Syntactic Plane Decoupling)**: In languages supporting computed member declarations or access (such as ECMAScript `*[Symbol.iterator]()` or `[inspectSymbol]()`), computed brackets `[` and `]` delimit an autonomous expression evaluation plane rather than an identifier. Inner tokens are evaluated according to runtime expression semantics (variables, properties, types, arithmetic) and remain on their native tiers (Base0 Grey `#839496` for identifiers), strictly decoupling computed keys from routine declarations in Blue (`#268BD2`).
     - **Runtime Global Singletons vs. Member Invocations**: Global singletons provided by the execution host (`console`, `process`, `globalThis`, `window`, `document`) fulfill the semantic role of ambient environmental receivers in Solarized Magenta (`#D33682`), while their routine invocations (`.log()`, `.exit()`) strictly remain in calm Base0 Grey (`#839496`) under Built-in Routine Invariance.
     - **Sentinels vs. Types in Tri-State Logic**: In SQL and systems programming, sentinel literals (`NULL`, `None`, `nil`, `_`, `std::nullopt`) represent missing states or wildcards and are classified strictly as constants in Solarized Magenta (`#D33682`), decoupling them from structural types and keywords.
     - **Positional Contextuality of Meta-Arguments**: Declarative identifiers fulfilling dual roles (such as Terraform `provider "aws" {` vs `provider = aws.west`) are disambiguated positionally: block headers join Green declarations, while assignment targets fall through to Base0 attributes.

     - **Compound Structured String Indivisibility (Regular Expressions)**: Indivisible compound patterns (such as ECMAScript `/^\/health[z]?$/i`) must not fracture internally on escaped delimiters (`\/`) or character classes (`[...]`). Delimiting slashes remain structural boundaries in Base0 Grey (`#839496`), the unified pattern body remains in Solarized Magenta (`#D33682`), and trailing flags (`i`, `g`, `m`) remain expression modifiers in Solarized Cyan (`#2AA198`).
     - **Atomic Compound Enclosures**: Enclosure sigils and their enclosed identifiers form inseparable cognitive units. Brackets, hashes, and directive names in Rust attributes (`#[derive(...)]`, `#![no_std]`), C++ attributes (`[[nodiscard]]`), Python decorators (`@dataclass`), and Java annotations (`@Override`) are unified in Solarized Violet (`#6C71C4`). 5. **Pillar V: Pushdown Automata State Machine Engineering**
   - *Core Premise*: Regex-based pushdown automata (`bat` / Syntect / Sublime Text) operate without compiler symbol tables or AST graphs. Achieving 1:1 parity with AST engines requires robust state machine engineering:
     - **Non-Greedy Transition Eagerness**: Pushdown state transitions must match structural framing prefixes (e.g. Markdown list sigils `^\s*([-*+]|\d+\.)(?=\s)` or quote sigils `^\s*(>)`) and *never* greedily consume downstream content (`(.*)$`). Consuming downstream characters on transition starves child contexts, skipping inline formatting, code spans, and links.
     - **Opening Delimiter Consumption vs. Lookahead Trap**: Context push rules must consume their opening delimiters (`match: '({{ident}})\s*(\()'` with capture 2 scoped to punctuation) rather than using lookaheads (`(?=\()`). Non-consuming lookaheads leave delimiters in the buffer to be consumed by inner rules, breaking pop condition symmetry and permanently trapping the parser in corrupted child states.
     - **Positional & Boundary Anchoring**: In indentation-sensitive or statement-delimiter-free syntaxes (Python, YAML, Markdown), rules must enforce line-initial anchors (`^\s*`) and negative lookaheads (`(?!\s*[=:])`) to prevent statement block headers (`try:`, `finally:`) from poisoning expression contexts.
     - **Composite Operator Deconstruction**: Glued operator-operand constructs (`>&2`, `2>&1`, `*ptr`) must be deconstructed at lexing time so operators remain Base0 Grey while numeric file descriptors retain Solarized Magenta (`#D33682`).
     - **Statement Arm Isolation**: Context-dependent statement blocks (such as shell `case ... in ... esac` arms) require dedicated pushdown contexts (`case-body`) to prevent line-initial pattern labels from being misparsed as command invocations in Blue.
     - **Contextual Polysemy Disambiguation**: Multi-purpose punctuation symbols (`*`, `@`, `#`) must be disambiguated by structural containment: SQL `*` in projection (`SELECT *`) vs binary arithmetic (`a * b` in Base0); shell `@` in parameter expansions (`$@` in Magenta) vs array subscripts (`${arr[@]}` in Cyan).
     - **Punctuation-Safe Word Tokenization**: Plain-text fallback rules must segregate non-space runs into word runs (`[^\s`*!_\[\]~()]+`), punctuation clusters, and fallback characters, preventing punctuation enclosures (`(**Debian/Ubuntu**,`) from swallowing adjacent markup delimiters.
     - **Multi-State Grammar Sequencing for Tabular Topology**: Pushdown automata must model tabular layouts as a multi-stage topological state machine (`table` $\to$ `table-after-header` $\to$ `table-body`) to distinguish Base1 headers from Base0 data cells.
      - **The Lookaround Guard Protocol for Contextual Keywords**: Contextual keywords that double as identifier positions (such as ECMAScript `of`, `in`, `catch`, `finally`, `default`) must be guarded by surrounding syntactic slots: negative lookbehinds `(?<!\.)` prevent chained method calls (`Array.of()`, `promise.catch()`) from triggering control flow Yellow, while negative lookaheads `(?!\s*:)` prevent object literal properties (`{ of: 1 }`) from matching.
      - **Computed Member Pushdown States**: State machines must push an autonomous expression context upon matching opening computed member brackets `\[` and pop on `\]`, delegating inner evaluation to the expression pipeline rather than greedily capturing bracketed spans as routine declarations.
      - **Lookahead Key Partitioning for Dotted Paths**: In serialization and configuration grammars (such as TOML), dotted key sequences (`pool.min_size`, `limits.per_minute`) must partition path segments using lookahead assertions `(?:\b[A-Za-z0-9_-]+\b)(?=\s*\.)` to cleanly distinguish dot accessors from value expressions without premature context popping or delimiter leakage.

6. **Pillar VI: Tree-sitter AST Query Hierarchy & Cascade Engineering**
   - *Core Premise*: Neovim's Tree-sitter architecture evaluates declarative S-expression pattern queries over concrete syntax trees. Robust query design prevents AST shadowing and ensures seamless polyglot injection:
     - **Root Fallback Invariance (The Cascade Principle)**: Root query capture groups (`@function.call = Base0`, `@function.builtin = Base0`, `@keyword.import = Violet`, `@variable.builtin = Magenta`) must strictly mirror the universal semantic contract. Contradictions in root highlights corrupt every embedded polyglot block and newly installed grammar. Aligning root captures enables hundreds of lines of repetitive per-language overrides to be pruned.
     - **Leaf-Node Dominance & Priority Predicates for Compound Sigils**: Parent container captures do not override child leaf nodes without explicit leaf captures or priority weighting (`#set! priority 120`). In compound AST nodes (such as Markdown alert callouts `[!NOTE]` or XML CDATA opening delimiters `<![CDATA[`), boundary leaf tokens (like brackets `[` and `]`) must be targeted directly with priority predicates (`(CDStart "[" @module (#set! priority 130))`) to prevent generic punctuation rules from fracturing compound enclosures.
     - **The Transparent Capture Fallthrough Trap (Extmark Attribute Cascading)**: In Neovim's extmarks highlight engine, multiple Tree-sitter captures can attach to the same token range. If a higher-priority capture specifies `nil` for an attribute (such as `fg = nil` in `@none`), the renderer does not clear the attribute—it transparently falls through to the next capture in the stack that defines a value. Resetting an upstream-highlighted token to neutral canvas Base0 Grey (`#839496`) must never rely on `@none`; it requires binding the token to a concrete capture with an explicit Base0 Grey definition (such as `@markup.raw.block` for code blocks or `@variable`) reinforced by language-scoped overrides (`["@markup.raw.xml"] = { fg = colors.base0 }`).
     - **Autonomous Language Tree Injection Hygiene & Runtimepath Precedence**: Language injections instantiate autonomous `LanguageTree` child parsers that supersede and bypass all syntax rules of the host document. Injections must never match containers unconditionally (e.g. injecting JS into any element named `<script>`) without structural guards (such as `type="text/javascript"` attributes). Because base injection queries (`injections.scm`) do not concatenate with `;; extends`, the workstation orchestrator must guarantee user configuration (`~/.config/nvim/queries/`) maintains unconditional precedence at index 1 of Neovim's `runtimepath`.
     - **Query Stream Ordering**: In Tree-sitter query streams, broader generic captures occurring later silently supersede earlier specific captures unless guarded by priority assertions. Specialized domain rules (such as dunder attributes `__name__` or qualified receivers) must be defended with explicit precedence.
     - **Polyglot Code Block Injection Isolation**: Markdown code block injections dynamically invoke the target language's Tree-sitter parser, executing the full syntax contract of the embedded language with strict scope boundaries.
     - **Standard Library Class Desensitization & Global Precedence**: Standard library runtime classes (`Date`, `Object`, `Math`, `Promise`, `Error`) must be prioritized to `@type` (Base0 Grey `#839496`) over upstream generic `@type.builtin` captures to prevent canvas fracture. Host runtime globals (`process`, `globalThis`) must be extended into `@variable.builtin` without excessive priority weighting that would override local function definitions (`function process()`).
     - **Base Query Supersedure for Metadata Elimination (The OSC 8 Hyperlink Trap)**: Tree-sitter query metadata (such as `(#set! @capture url ...)` in upstream HTML queries) attaches directly to extmarks during `query:iter_matches`. When present, Neovim's TUI emits OSC 8 terminal escape sequences (`\e]8;;<URL>\e\`), rendering tokens as clickable terminal hyperlinks in modern emulators like Ghostty. Because query metadata is collected cumulatively across all matching query files on `runtimepath`, setting a higher-priority highlight in `after/queries/` does NOT suppress metadata from upstream base queries. Eliminating rogue metadata requires superseding the base query directly in `~/.config/nvim/queries/<lang>/highlights.scm` without `;; extends`.
     - **Diagnostic Underline Isolation & Hyperlink Extmark Suppression**: Diagnostics and document link providers in Neovim operate on an independent layer above syntax highlighting. If `DiagnosticUnderline*` groups specify a foreground color (`fg`), Neovim colorizes the text characters themselves, overwriting the underlying syntax highlighting (e.g. turning Cyan URLs into Yellow warning text). Overriding `DiagnosticUnderline*` with `fg = "NONE"` ensures diagnostic severity is rendered exclusively as an undercurl/underline using `sp`, preserving syntax color fidelity. Furthermore, nullifying `client.server_capabilities.documentLinkProvider = nil` eliminates rogue clickable extmarks on URLs in code.
     - **Recursive AST Query Depth Unrolling**: When Tree-sitter grammars (such as `tree-sitter-toml`) model dotted paths as nested binary trees (`(dotted_key (dotted_key (bare_key)) (bare_key))`), highlight queries must explicitly unroll pattern depths up to the grammar's depth limit. This ensures parent container semantics (`table` header Blue vs `pair` key Green) cascade down to all path segments without leaking into adjacent value expressions.
     - **Single-Source-of-Truth Query Architecture (Base Supersedure vs. Runtime Extension)**: Neovim supports two query locations: `queries/<lang>/` (evaluated first, for base supersedure) and `after/queries/<lang>/` (evaluated last, with `;; extends` for additive rules). When a grammar requires eliminating upstream directives (such as rogue `url` metadata in HTML) or preventing broad structural selector swallowing (as in CSS, HTML tags, and Properties), the base query must be superseded directly in `queries/<lang>/highlights.scm` **without `;; extends`**. Conversely, when extending upstream distro queries additively (as in Go, Rust, Python, Bash), rules belong in `after/queries/<lang>/highlights.scm` with `;; extends`. Never maintain duplicate highlight queries across both directories for the same language: dual sets produce conflicting priority stacks and double AST traversal overhead.
     - **Document-Order Rule Precedence & Catch-All Fallback Sequencing**: In Tree-sitter query evaluation, rules at equal priority are evaluated sequentially in document order. When defining a fallback rule alongside specialized predicate captures (e.g. in Java Properties or JSON), generic catch-all patterns (`(value) @string`) must **always precede** specialized predicate rules (`((value) @number (#lua-match? ...))`). Placing catch-alls after specialized rules in document order causes the broader pattern to match downstream and overwrite specific syntax captures.

7. **Pillar VII: Standalone Subsystem Independence & LTS Currency**
   - *Core Premise*: Workstation developer environments must be completely decoupled from distro packaging lag and upstream dependency rot:
     - **Standalone Grammar Independence (Zero Dependency Traps)**: Grammars in `syntaxes/` must be 100% self-contained, declaring all contexts locally without external TextMate includes (`Packages/Git Formats/...` or `source.go.embedded...`). Missing external dependencies trigger silent fallback cascades to obsolete regex packages that poison modern themes (e.g. turning SQL column names Magenta).

This repository provisions actively supported LTS runtimes via `mise` and decouples syntax highlighting through maintained, version-controlled grammars in `syntaxes/` and query overrides in `after/queries/`.

## 4. Step-by-Step Task Recipes for Agents

### Recipe A: Adding or Updating a Developer Toolchain
1. Edit `.mise.toml` to declare the tool:
   - Use `"lts"` if the tool ecosystem supports LTS releases (e.g. `java = "lts"`, `node = "lts"`).
   - Use `"latest"` for all other stable tools (e.g. `go = "latest"`, `python = "latest"`, `neovim = "latest"`).
2. If client CLI utilities are needed from distro package managers, add them to `modules/00-packages.sh`.
3. Update `.mise.toml` validation in `tests/test-system-setup.sh`.
4. Run `make test` and `make lint` to verify.

### Recipe B: Adding a Setup CLI Switch / Option
1. Update `setup.sh` argument parser (`while [ $# -gt 0 ]; do ... done`).
2. Implement `--dry-run` and live behavior within the relevant `modules/<NN>-*.sh` script.
3. Add a test case in `tests/test-system-setup.sh` asserting both `--help` and `--dry-run` behavior.
4. Update the CLI Options table in `README.md`.
5. Update `AGENTS.md` if the option establishes a new invariant.
6. Run `make test` and `make lint`.

### Recipe C: Adding a Custom Git Workflow or Developer Shortcut
1. Add the alias to `dotfiles/.aliases` (or function to `dotfiles/.zsh-functions` if multi-line).
2. Ensure no standard Oh-My-Zsh git aliases are duplicated.
3. Add the alias/function name to the assertion list in `tests/test-zsh.zsh`.
4. Run `make test` and `make lint`.

### Recipe D: Modifying Environment Variables or PATH
1. Edit `dotfiles/.environment-variables`.
2. Ensure XDG paths (`XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`) are respected.
3. Update assertions in `tests/test-env.sh`.
4. Run `make test` and `make lint`.

### Recipe E: Adding a New Managed Dotfile
1. Drop the file or directory directly into `dotfiles/` (e.g. `dotfiles/.gitconfig`, `dotfiles/.tmux.conf`).
2. Dotfiles are automatically discovered and mirrored to `$HOME` by `modules/10-dotfiles.sh` and cleaned up by `modules/99-uninstall.sh`.
3. Add assertion to `tests/test-dotfiles.sh`.
4. Run `make test` and `make lint`.

### Recipe F: Adding a Standalone CLI Utility
1. Drop the executable script into `bin/` (e.g. `bin/my-util`).
2. Make it executable (`chmod +x bin/my-util`) and start with `#!/bin/bash` + `set -euo pipefail`.
3. It is automatically symlinked to `~/.local/bin/my-util` by `modules/20-bin.sh` and cleaned up by `modules/99-uninstall.sh`.
4. Add unit test to `tests/test-bin.sh`.
5. Run `make test` and `make lint`.

### Recipe G: Adding a New Provisioning Module
1. Create `modules/<NN>-<feature>.sh` (numbered between 00 and 99 by execution order).
2. Include standard shebang, `set -euo pipefail`, and source `lib/log.sh`, `lib/os.sh`, `lib/symlink.sh`.
3. Respect standard environment flags: `DRY_RUN`, `OS`, `ARCH`.
4. Wire the module into `setup.sh`.
5. Add test coverage and verify with `make test` and `make lint`.

## 5. Anti-Patterns & Common Traps (What NOT to Do)

| Anti-Pattern | Why It Breaks | Correct Implementation |
| :--- | :--- | :--- |
| **Masking Startup Warnings (`2>/dev/null`)** | Hides real syntax/configuration errors from the user. | Fix the root cause (trust configs via `mise trust`, install missing runtimes via `mise install`). |
| **Hardcoding Dotfile Lists in Scripts** | Requires editing bash arrays whenever dotfiles change. | Drop dotfiles in `dotfiles/`; let `modules/10-dotfiles.sh` auto-discover and mirror. |
| **Inlining Module Logic into `setup.sh`** | Re-creates a bloated, unmaintainable monolithic script. | Keep `setup.sh` strictly as an orchestrator CLI; place logic into `modules/<NN>-<name>.sh`. |
| **Blind `ln -sfn` Over Existing Directory** | Creates a nested symlink (`~/.config/nvim/nvim -> ...`) instead of replacing the directory. | Use `lib/symlink.sh` (`link_dir` / `link_file`) which backs up physical directories to `.bak.<timestamp>`. |
| **Hardcoding Distro Neovim Paths** | Ubuntu 22.04 apt installs Neovim 0.9.5, which crashes modern LSP plugins. | Rely on modern Neovim provisioned via `mise` (`neovim = "latest"`). |
| **Letting Go Pollute `$HOME/go`** | Clutters user home directory. | Export XDG variables: `GOPATH="$HOME/.local/share/go"` and `GOCACHE="$HOME/.cache/go-build"`. |
| **Installing Database Daemons by Default** | Consumes system memory, starts unwanted background services, and opens local listening ports. | Install only client CLIs by default; require `--with-postgres`, `--with-mariadb`, or `--db <engine>` for server daemons. |
