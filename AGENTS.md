# Agent guidelines and repository architecture for home-settings

This repository provides automated workstation provisioning, dotfiles, shell environments, and developer toolchains for modern Unix systems: Debian-based Linux (Ubuntu, Debian, Pop!_OS), RHEL-based Linux (Fedora, RHEL, CentOS Stream, Rocky Linux), and macOS.

Any AI agent interacting with or modifying this repository must strictly adhere to the instructions and invariants below.

## 1. Non-negotiable core invariants and guardrails

| Rule | Invariant | Description |
| :--- | :--- | :--- |
| Never | No hardcoded personal paths | Never commit paths containing personal usernames like `/home/<username>/`, `/Users/<username>/`, or Windows user profiles. Always use `$HOME`, `${XDG_DATA_HOME:-$HOME/.local/share}`, `${XDG_CONFIG_HOME:-$HOME/.config}`, or `${XDG_CACHE_HOME:-$HOME/.cache}`. |
| Never | No employer-internal names in tracked files | This repository is public. Never commit company-internal hostnames, short links, monorepo paths, or internal tool or product names (in code, tests, docs, or commit messages), and never write tests that grep for them. Machine-specific rules belong in untracked hooks: `Ctrl+Click` link rules (`ide_resolve_link WORD CWD`) and workspace session-naming rules (`ide_session_name DIR`) in `${XDG_CONFIG_HOME:-$HOME/.config}/ide/links.sh` (overridable via `$IDE_LINK_RULES`) and prompt overrides in `${XDG_CONFIG_HOME:-$HOME/.config}/zsh/p10k.local.zsh` (sourced by `.p10k.zsh` before `p10k reload`). |
| Never | No blind error suppression | Never redirect `stderr` to `/dev/null` or use blanket quiet flags (`MISE_QUIET=1` and similar settings) in startup files (`.zshrc-addendum`, `.bashrc-addendum`) or orchestrators. Always resolve the root cause (such as trusting configs or installing missing toolchains). |
| Never | No default heavy daemons or GUI apps | Heavyweight database server daemons (PostgreSQL, MariaDB) and GUI applications (Chrome, VS Code) must never be installed by default. Only lightweight client CLI tools (`psql`, `mariadb-client`) are installed unless opted into via `--with-postgres`, `--with-mariadb`, `--db <engine>`, or `--with-gui`. |
| Never | No hardcoded dotfile arrays in setup | Never maintain hardcoded lists of dotfile paths in `setup.sh`. All dotfiles must be auto-discovered declaratively by `modules/10-dotfiles.sh` and mirrored to `$HOME`. |
| Never | No redundant standard Git aliases | Standard Git aliases (`ga`, `gst`, `gco`, `gd`, `gb`, `gl`, `gp`) are provided directly by Oh-My-Zsh's `git` plugin. Keep `.aliases` pruned to custom workflows (`gcommit`, `gamend`, `gsync`, `guser-branch`, `gprune`, `gpurge`). |
| Never | No Starship prompt | The shell prompt is strictly single-line Powerlevel10k Solarized Dark. Never re-introduce `starship`. |
| Never | No EOL Java releases | Only actively supported Java LTS releases are allowed (Java 17 LTS, Java 21 LTS, Java 25 LTS). Deprecated or EOL versions (Java 8, Java 11) must never be used. Runtimes are managed declaratively via `.mise.toml` (`java = "lts"`). |
| Never | No nested directory symlinks | When symlinking directory trees (such as `${XDG_CONFIG_HOME:-$HOME/.config}/nvim`), always check if the target is an existing physical directory. If so, back it up (`nvim.bak.<timestamp>`) before calling `ln -sfn` to prevent creating nested links (`~/.config/nvim/nvim`). Enforced via `lib/symlink.sh`. |
| Never | No chromatic noise on scope qualifiers | Never color prefix qualifiers (`std::`, `boost::`, `context.`, `fmt.`) in accent colors. Only formal declaration sites (`package main`, `namespace core::telemetry`, `using namespace ...`) receive Violet (`#6C71C4`); qualifiers in code strictly remain in calm Base0 Grey (`#839496`). |
| Never | No semantic flipping for factory functions | Never color factory function calls (`NewClusterNode`, `NewService`) in Yellow as constructors. In languages like Go where constructors are standard functions, function invocations strictly remain in calm Base0 Grey (`#839496`) alongside all routine invocations. |
| Never | No token fracturing in structured strings or attributes | Never fracture compound constructs like Go struct tags (``` `json:"port"` ```), C++ attributes (`[[nodiscard]]`), Rust attributes (`#[derive]`, `#[inline]`), printf format specifiers (`%s\n`), diff lines (`+ line`), or Rust lifetimes (`'a`, `'static`) into multi-colored checkerboards. They must remain unified in their primary accent. |
| Never | No piped multi-kilobyte variables to early-terminating consumers | Under `set -euo pipefail`, piping multi-kilobyte strings into early-terminating consumers (such as `echo "$OUT" \| grep -q`) triggers `SIGPIPE` (exit 141) on the producer. Always use Bash here-strings (`grep -Fq "$pattern" <<< "$OUT"`) or temporary files to ensure 100% deterministic test execution. |
| Never | No Yellow in Markdown headings | Never use Solarized Yellow (`#B58900`) for Markdown headings. Headings strictly follow Semantic Architecture: H1 Orange (`#CB4B16`), H2 Blue (`#268BD2`), H3 Violet (`#6C71C4`), H4 Base1 (`#93A1A1`), H5 and H6 Base0 (`#839496`), with `#` delimiter sigils in Base01 (`#586E75`). Yellow is reserved exclusively for control flow and execution pathways inside embedded code blocks. |
| Never | No artificial bold typography in headings | Never apply bold font styles across Markdown headings (`bold = false`). Monospace character metrics and zero-jitter layout are strictly preserved. Explicit author bold (`**bold**`) remains Base1 Bold (`#93A1A1`). |
| Never | No high-contrast static prompt icons | The shell prompt OS icon must never be rendered in high-luminance colors (Base2 `#EEE8D5` or Base1 `#93A1A1`) that outshine actionable semantic landmarks like the current directory path (Blue `#268BD2`) or Git branch status (Green or Yellow). It strictly remains in calm Base0 (`#839496`). |
| Never | No perpendicular box-drawing shelf separators | Subsegment separators within the prompt shelf must use thin directional chevrons (`\uE0B1` on left, `\uE0B3` on right), never full-height box-drawing bars (`│`), to eliminate visual grid cages and shell pipe (`\|`) ambiguity while preserving kinetic horizontal momentum. |
| Never | No asymmetrical right prompt margin gap | Never allow Zsh's default 1-space padding to detach the right prompt from the screen margin. Right prompt must remain flush against the right edge via `ZLE_RPROMPT_INDENT=0` configured after prompt expansion, matching the flush left prompt margin (`POWERLEVEL9K_LEFT_PROMPT_FIRST_SEGMENT_START_SYMBOL=''`). |
| Never | No cross-domain collisions in filesystem tools | In `LS_COLORS` and `EZA_COLORS`, never assign directory Blue (`#268BD2`) or archive Orange (`#CB4B16`) to cryptographic keys and certificates (`.key`, `.pem`, `cr`). Cryptographic credentials strictly belong to Magenta (`#D33682`), isolated from general navigation. |
| Never | No uncalibrated ANSI slot assumptions | In terminal profiles with custom 16-color palettes, never assume basic ANSI 33 is Orange or ANSI 35 is Violet. Tools emitting basic ANSI codes (`dircolors`) must be calibrated to the terminal emulator's concrete slot mapping (such as Ghostty slot 9 or ANSI `91` for Orange, and slot 13 or ANSI `95` for Violet). |
| Never | No greedy computed member captures | Computed member keys (`[expr]`) must never be captured greedily as routine declarations in Blue (`#268BD2`). Brackets `[` and `]` delimit an arbitrary runtime expression evaluation plane whose inner tokens remain on their native semantic tiers (Base0 Grey `#839496` for identifiers). |
| Never | No unbounded contextual keyword trapping | Contextual keywords (`of`, `in`, `catch`, `finally`) must never be matched without surrounding syntactic guards. Always use negative lookbehinds `(?<!\.)` to prevent method invocations (`Array.of()`) and negative lookaheads `(?!\s*:)` to prevent object property labels (`{ of: 1 }`) from falsely masquerading as Yellow control flow. |
| Never | No transparent capture fallthrough for canvas neutralization | Never rely on `@none` (which has `fg = nil`) to reset an upstream-highlighted token to Base0 Grey. In Neovim's extmarks renderer, attributes cascade across capture stacks, allowing underlying colors (like `@markup.raw` Cyan) to show through. Always map to a concrete capture with an explicit Base0 Grey binding (`@markup.raw.block`, `@variable`) and reinforce with language-scoped overrides (`@markup.raw.xml`). |
| Never | No unconditional language injections | Never inject child languages based solely on generic container names (`<script>`) without explicit attribute qualifiers (`type="text/javascript"`). Blind injections bypass the host grammar, break non-matching payload scripts (shell scripts, SQL), and lock tokens inside an incompatible foreign AST. |
| Never | No rogue OSC 8 hyperlink metadata | Never allow Tree-sitter queries to emit `(#set! @capture url ...)` directives that attach `metadata.url` to extmarks. In modern terminals (Ghostty, GNOME Terminal), this causes Neovim's TUI to emit OSC 8 terminal escape sequences, turning URLs into clickable hyperlinks. Upstream queries containing `url` metadata must be superseded at the base query level (`queries/<lang>/highlights.scm` without `;; extends`), because `after/queries/` cannot suppress metadata collected by `iter_matches`. |
| Never | No diagnostic foreground mutation of syntax | Never set `fg` on `DiagnosticUnderline*` groups (`Error`, `Warn`, `Info`, `Hint`). Always set `fg = "NONE"` alongside `sp` and undercurl or underline styles. Diagnostic squiggles indicate diagnostic severity strictly through underline color (`sp`), leaving the underlying token's syntax highlighting completely uncorrupted (preventing URLs or strings from turning yellow or red). |
| Never | No rogue document link providers | In Neovim LSP configs, always nullify `client.server_capabilities.documentLinkProvider = nil` in `LspAttach`. Document link providers attach hyperlink extmarks that turn string URLs into clickable OSC 8 links and interfere with syntax highlight colors. |
| Never | No remote schema LSP validation for sample code | Never enable remote schema downloading or validation in language servers (`jsonls.settings.json.validate = { enable = false }`, `yamlls.settings.yaml.validate = false`). Remote schema lookups on mock or sample URIs (such as `https://api.example.com/...`) trigger DNS resolution failures and spurious diagnostic warnings. |
| Never | No Yellow in declarative data, config, or stylesheet documents | Never use Solarized Yellow (`#B58900`) in JSON, YAML, TOML, XML, HTML, CSS, Java Properties, or Protocol Buffers (`.proto` and `.textproto`) documents. Control flow Yellow is reserved strictly for imperative execution pathways (`if`, `return`, `for`, `switch`, `match`). CSS properties, configuration keys, and Protobuf structural keywords (`returns`, `message`, `enum`, `service`, `rpc`, `option`) and scalar field keys strictly belong to Solarized Green (`#859900`), and custom property identifiers, variable calls, and custom message types strictly remain in calm Base0 Grey (`#839496`). |
| Never | No fracturing or false declaration of interpolated keys | In property files and templated configurations, never color variable interpolation keys (`${key}`) in Green as if they were property declarations. Interpolation wrappers (`${`, `}`) and referenced keys strictly remain in calm Base0 Grey (`#839496`). |
| Never | No flat structural hierarchy in TOML | Never color TOML table section headers (`[table]`, `[[array]]`) in the same color as mapping keys (`key =`). Table headers strictly belong to Solarized Blue (`#268BD2`) as macro-level section boundaries, and mapping keys belong to Solarized Green (`#859900`). |
| Never | No string escapes for temporal literals | Never capture unquoted TOML date-times (`2025-09-14T08:30:00Z`) as `@string.special` (Cyan). Unquoted temporal scalars strictly belong to Solarized Magenta (`#D33682`) alongside numbers and booleans. |
| Never | No fracturing of CSS custom properties or compound keywords | Never permit token fracturing of custom property identifiers (`--color-base03`, `--bg-primary`) or compound sizing keywords (`auto-fill`, `auto-fit`, `inline-block`, `ease-in-out`) into pseudo-numbers, disjoint prefixes, or dangling operators. They must be captured atomically in calm Base0 Grey (`#839496`). |
| Never | No token fracturing in hex colors or prefixed literals | Never separate the `#` in hex colors (`#002b36`) as a delimiter or operator. The leading `#` is an atomic literal prefix in Solarized Magenta (`#D33682`). ID selectors (`#dashboard-grid`) strictly belong to Solarized Blue (`#268BD2`), completely isolated from numeric color literals. |
| Never | No catch-all selector priority swallowing in Tree-sitter | Broad structural selector captures (such as `((selectors) @type (#set! "priority" 125))`) must never swallow leaf tokens. Attribute string values (`"healthy"` in `[data-status="healthy"]`), nesting parent combinators (`&`), attribute names (`data-status`), and custom properties must be shielded with priority `>= 130`. |
| Never | No dual-redundant Tree-sitter query sets | Never maintain duplicate query definitions across `queries/<lang>/` (base supersedure) and `after/queries/<lang>/` (runtime extensions). Use `after/queries/` with `;; extends` strictly for additive extensions to upstream distro queries; use `queries/` without `;; extends` when fully superseding upstream queries (such as eliminating rogue metadata or broad selector swallowing). Never define both for the same language. |
| Never | No inverted rule ordering for catch-all fallbacks | In Tree-sitter query architecture, generic catch-all patterns (such as `(value) @string`) must always precede specialized predicate rules (`((value) @number (#lua-match? ...))`). Placing catch-alls after specialized rules in document order causes the fallback to overwrite specific syntax captures. |
| Never | No unpinned degradation of modern syntax standards | Never permit modern language features (such as CSS Container Queries Level 3 with named container statements `@container name (...)`) to collapse into unhighlighted `ERROR` nodes due to outdated distro-packaged parsers. Upstream Tree-sitter revisions must be declaratively pinned (`parsers.<lang>.install_info.revision`) inside a `User` `TSUpdate` autocmd so `nvim-treesitter`'s `reload_parsers()` cannot wipe the pin. |
| Never | No chromatic noise in editor framing and navigation chrome | Non-code UI chrome (line numbers, split borders, float borders, gutter columns) must never use bright accent colors that compete with code semantics. Line numbers follow the monochromatic luminance scale (Base01 inactive, Base1 active on Base02), and window borders strictly remain in Base01. |
| Never | No frozen `gitstatusd` or `libgit2` prompt daemon | Never enable `gitstatusd` (`POWERLEVEL9K_DISABLE_GITSTATUS=true` must remain set in `.p10k.zsh`). The 2022 `gitstatusd` (`libgit2`) binary fails on modern Git `reftable` (`extensions.refstorage = reftable`) and SHA-256 repositories. VCS segments in both Zsh (`_p9k_solarized_prompt_vcs`) and Bash (`_solarized_bash_prompt`) must use single-fork `git --no-optional-locks status --porcelain=v2 --branch`, zero-fork `.git/config` remote host icon resolution (``, ``, ``, ``), and non-blocking OSC 8 `<branch>@<N>` pull or merge request hyperlinks across GitHub, GitLab, Bitbucket Cloud, Bitbucket Server and Data Center, and Gitea, Forgejo, and Codeberg (via Tier 0 `.git/config` `branch.<name>.pr`, `prurl`, or `merge` and Tier 0.5 `${XDG_CACHE_HOME:-$HOME/.cache}/git-pr-prompt/*.state` populated asynchronously by `_p9k_vcs_refresh_pr_cache` and `_solarized_vcs_refresh_pr_cache`). |
| Never | No in-place file unlinking under daemon emulators | Never delete or unlink active font files in-place with raw `rm -f "$target"` while terminal servers (`gnome-terminal-server`) are active. Always download to atomic temporary files (`$cached.tmp.$$.$BASHPID`) and install via atomic `mv -f` to preserve open inodes and prevent tofu missing glyphs. Always provision official `ryanoasis/nerd-fonts` v3.3.0+ `MesloLGS Nerd Font Mono` (`MesloLGSNFM-Regular`), maintain the `10-meslo-nerd-font.conf` fontconfig alias mapping legacy `MesloLGS NF` to `MesloLGS Nerd Font Mono`, and configure terminal emulators directly to `MesloLGS Nerd Font Mono 12` (`MesloLGSNFM-Regular` on macOS). |
| Never | No root-table `Ctrl+hjkl` traps or hidden `_swap` IDE windows | Never bind `bind -n C-h/j/k/l` in `dotfiles/.tmux.conf` or map `<C-h/j/k/l>` in Neovim terminal mode (`"t"`), which break `Ctrl+L` (clear), `Ctrl+J` (newline), `Ctrl+K` (kill line), and `Ctrl+H` (backspace) in shells and AI CLIs. Keep `<C-h/j/k/l>` strictly internal to Neovim splits (`internal_split_nav`), use `Alt+h/j/k/l` (`M-h/j/k/l`) for universal 2D spatial focus navigation across Neovim (`n/i/v/t`), Vim (`n/v/i`), and Tmux, use `Alt+Shift+H/J/K/L` (`ide --swap left\|down\|up\|right`) for directional pane swapping and `Alt+Left/Down/Up/Right` (`Prefix + H/J/K/L`) for keyboard resize, keep all visible IDE panes (`Editor`, `Shell`, `AI`) in a single window (`ide`, locked with `allow-rename off`) with a single Neovim server and `mini.files` (`Space e` or `Space E`), park hidden panes non-destructively via `_ide_park_<role>` (`Alt+Shift+E` and `Alt+Shift+T`, `ide --toggle-editor\|--toggle-term\|--toggle-ai`, tracked via `@ide_*_parked` in the 3-state `@ide_tab_*` status bar and clickable via `ide --status-click`), surface the interactive keybinding cheatsheet popup via `Alt+?`, `Space ?`, or `Prefix + ?` (`ide --keys`), and never kill or respawn the AI Agent pane on `icd` or `ide --cd`. |
| Never | No AI transcript scraping or custom file tree and quit hijacks | Never scrape AI conversation logs (`~/.gemini/*/brain/*`, `~/.claude/*`) in `init.lua` or `bin/ide`, never maintain a custom Lua sidebar (`SolarizedIdeTree`) or `IdeFollow` polling timer, and never remap native Neovim `:q`, `:wq`, `:qa`, or `:wqa`. Use native `opt.autoread = true` and `SolarizedAutoRead` (`FocusGained`, `BufEnter`, `CursorHold`, and `CursorHoldI` invoking `silent! checktime`) for external AI edits, `Telescope git_status` (`Space gs`) to review modified files, left-anchored `mini.files` (`Space e` or `Space E`, `max_number = 2`, `SolarizedMiniFilesWindow` full-width right preview) for file exploration, `render-markdown.nvim` (`Space m`) with `SolarizedMarkdownReadability` (`wrap`, `linebreak`, `breakindent`) for in-buffer Markdown reading, and `:Q`, `:Quit`, `Space q`, or `Alt+q` for workspace termination. Setup modules must never hot-reload live servers (`tmux source-file`, `luafile` into `nvim-ide-*.sock`). |
| Never | No local `:0` display spoofing over SSH or custom clipboard overrides | Never probe `/tmp/.X11-unix/X0` or `wayland-0` when `SSH_CONNECTION`, `SSH_TTY`, or `SSH_CLIENT` is set (in `init.lua`, `dotfiles/.tmux.conf`, or `bin/ide`), which diverts SSH yanks into an unreachable local desktop X server instead of OSC 52. Never override `vim.g.clipboard` in `init.lua`; rely on Neovim's built-in clipboard provider (`opt.clipboard = "unnamedplus"`). In `dotfiles/.tmux.conf`, enable `terminal-features '*:hyperlinks'` (resetting `set -g terminal-features ""` first and never setting `*:Hls@` so OSC 8 links pass through to the outer terminal) with `set-environment -g FORCE_HYPERLINK 1` so tmux captures inner-pane OSC 8 links into `#{mouse_hyperlink}` for `Ctrl+Click` and `Alt+Click` (`C-MouseDown1Pane` and `M-MouseDown1Pane`, with `recover_split_osc8_href` in `bin/ide` recovering 1st-character and `<branch>@<N>` suffix split OSC 8 links) routing into Neovim or the browser, stamp a single context jump mark (`normal! m'`) before `keepjumps edit` and `keepjumps call cursor(...)` in `nvim_remote_file()` and map `Mouse4` and `Mouse5` (`MouseDown8Pane` and `MouseDown9Pane` in tmux, `<X1Mouse>` and `<X2Mouse>` in Neovim and Vim) to `C-o` and `C-i` so jumping back after `Ctrl+Click` or `Alt+Click` takes one step, use `copy-pipe-no-clear` on mouse drag, double-click, and triple-click so selections stay highlighted for `Alt+c`, and pin root `MouseDown1Pane` to `select-pane -t = \; send-keys -M` (never a shell interceptor). |
| Never | No guessed or prefix-matched tmux session targets | `bin/ide` must never let tmux choose a session. Automated callers always name it: tmux key bindings pass `'#{session_name}'`, and every Editor call goes through `ide_job()` in `init.lua`, which appends the pane's `$IDE_SESSION`. For commands typed by hand, an untargeted `tmux display-message -p '#{session_name}'` answers with the most recently used session once the caller's pane is gone, so auto-detection resolves the caller's own `$TMUX_PANE` (or a run-shell job's session id, the last field of `$TMUX`) by exact id, requires the server pid from `$TMUX` to match `#{pid}`, and accepts only `ide`-managed sessions (`@ide_session`, `@ide_socket`, `@ide_main_win`), returning nothing otherwise. Session names default to the sanitized directory basename (overridable via `ide_session_name DIR` in `${XDG_CONFIG_HOME:-$HOME/.config}/ide/links.sh` or `$IDE_LINK_RULES`). Session targets are exact: session-type commands (`has-session`, `kill-session`, `attach-session`, `switch-client`, `list-windows`, `show-environment`, `set-environment`) take `-t "=NAME"`, and pane- or window-type commands (`show-options`, `set-option`, `display-message`, `list-panes`) take `-t "=NAME:"`, because a bare `-t NAME` prefix-matches (`foo` matching `foobar`) and tmux applies a leading `=` only to the target part the command expects (`list-panes -s -t =foo` still lists `foobar`). The Editor is closed with `--remote-send '<C-\><C-n><Cmd>qall!<CR>'`. |
| Never | No swallowed mouse resize drags | tmux border drags stay pinned (`bind -n MouseDrag1Border resize-pane -M`). `bin/ide` focus switches (`--toggle`, `--show-*`) never re-split, re-layout or resize visible panes, and parking and unparking (`--toggle-editor`, `--toggle-term`, `--toggle-ai`) records and restores custom pane sizes. |
| Never | No multi-line `-c` or unbounded headless Neovim invocations | Never pass multi-line strings or `lua << EOF` blocks to `nvim --headless -c "..."` (Neovim splits `-c` on `\n` into separate Ex commands and aborts on the first error before reaching `qa!`), and never rely on `vim.cmd("qa!")` inside a `-c` block that could throw an error. Always write multi-line Lua to a file and invoke `run_nvim_headless` (or `timeout 30 nvim --headless -u <init.lua> -c "luafile <script.lua>" -c "qall!" </dev/null`) so a separate trailing `-c "qall!"` and closed stdin guarantee termination. |
| Never | No blind screen-column link offsets or desynchronized Markdown navigation | In Neovim, link and table of contents navigation (`<C-LeftMouse>`, `<M-LeftMouse>`, `gx`, and buffer-local `gd` and `<CR>` in Markdown) must never rely on raw screen columns, rogue `(#set! @capture url ...)` OSC 8 terminal escapes in `markdown_inline` (which cause `tmux` and outer terminals to hijack `#anchor` and relative file clicks), or custom character-by-character string or fence parsers. Link extraction uses standard Tree-sitter AST traversal (`vim.treesitter.get_node({ ignore_injections = false })` for `inline_link` and `uri_autolink`, with `<cfile>` fallback) and queries `(atx_heading (inline) @h)` in the `markdown` Tree-sitter tree (automatically ignoring fenced code blocks and resolving GFM heading slugs and duplicate `-1` and `-2` suffixes), opens relative file paths with optional `#L42` line numbers or `#heading` fragments, routes `http(s)://` URLs via `bin/ide --open-link` (local browser or SSH OSC 52 clipboard) or `vim.ui.open`, falls back to LSP `vim.lsp.buf.definition()` or `<C-]>` tags, and records a single context jump mark (`normal! m'`) so `Mouse4` (`<X1Mouse>`) or `Ctrl+O` returns to the source position in one step. |
| Never | No polling hacks, cross-process state sync, or duplicated status chrome | Never use `tmux` `#(...)` shell-polling commands or periodic timers in `status-left` or `status-right`. Never spawn `tmux set-option` child processes from Neovim keystroke or buffer-edit autocmds (`TextChangedI`, `BufModifiedSet`) to mirror editor state into the tmux bar (which introduces subprocess churn and leaves stale state if a process exits abnormally). Never fake per-pane activity or bell badges across single-window panes via shell `precmd` hooks or terminal scraping. Never duplicate bottom shell prompt segments (Git branch, language toolchains, always-on CPU and RAM meters) in the top tmux header. Top status bar indicators must use 100% native, zero-fork, zero-polling `tmux` C format variables and event-driven workspace options (`#{scroll_position}/#{history_size}` in `COPY` mode, `#{?pane_synchronized,...}` for `SYNC`, `#{?#{||:#{!=:#{SSH_CONNECTION},},#{!=:#{SSH_TTY},}},...,}` for remote `#h` SSH host, and `@ide_workdir` for `icd` subdirectory divergence). |
| Never | No feature accretion in documentation | Never document new capabilities by merely appending bullet points to the end of a section. Appending creates flat, disjointed lists with buried keybindings. Always integrate changes holistically into the macro-to-micro architectural hierarchy, updating both the conceptual narrative and the dedicated reference tables. |
| Always | Zero-dependency portable `.vimrc` and `.bashrc-addendum` parity | `dotfiles/.vimrc` and `dotfiles/.bashrc-addendum` must remain self-contained so copying just those two files to a restricted remote server provides the inline Solarized Dark TrueColor and `cterm` Vim palette (`s:ApplySolarizedDark()`) and the `Base02` (`#073642`) shelf Bash prompt (`_solarized_bash_prompt()`) with remote VCS icons, clickable OSC 8 `@<N>` pull or merge request links, `LS_COLORS`, `LESS_TERMCAP_*`, and core Git workflow aliases. |
| Always | Modular stage architecture | Keep `setup.sh` strictly as an orchestrator CLI (~420 lines). Subsystem provisioning belongs in dedicated scripts under `modules/<NN>-<name>.sh` using shared helpers in `lib/`. |
| Always | LTS preference for Mise tools | For all tools defined in `.mise.toml`, specify `lts` whenever supported by the tool's ecosystem (`java = "lts"`, `node = "lts"`). For tools without an official LTS channel (Go, Python, Maven, Terraform, Rust, Neovim, Ripgrep, ShellCheck), default to `latest` stable. |
| Always | Modern Neovim via Mise | Modern Neovim (0.11+ and 0.12+) is provisioned via `mise` (`neovim = "latest"`), avoiding obsolete distro packages (such as Ubuntu's default 0.9.5). |
| Always | XDG Base Directory compliance | Keep `$HOME` clean of language runtime workspaces and cache clutter. Go workspace and cache must strictly point to XDG paths: `export GOPATH="${XDG_DATA_HOME:-$HOME/.local/share}/go"` and `export GOCACHE="${XDG_CACHE_HOME:-$HOME/.cache}/go-build"`. |
| Always | Idempotent and fail-fast scripts | All Bash scripts must begin with `set -euo pipefail`. Re-running `setup.sh` or `Makefile` targets must be completely safe, non-destructive, and produce identical results. |
| Always | Architectural top-down flow and dual representation | Technical documentation must follow the 4-tier architectural flow (mental model, structural layers, runtime engines, and toolchains) and maintain dedicated, formatted quick-lookup reference tables for shortcuts and commands. |

### Higher-order architectural pillars

- **Pillar I: The 3-tier semantic color contract and canvas tranquility**:
  - **Core premise**: Highlighting is not visual decoration; it is an ergonomic aid engineered to minimize cognitive load and saccadic fatigue during code reading, navigation, and review. Every palette color fulfills an invariant mental category across all programming languages, configuration syntaxes, and markup documents:
    - **Tier 1: Monotone ground (70–80% screen area) in Solarized Base0 and Base01**: Uses `#839496` and `#586E75` for standard text, variable identifiers, parameters, struct and field members, custom domain types and classes (`OrderRecord`, `Context`, `HashMap`, `Instant`, `ClusterNode`, `WorkerNode`, Java and Rust `String`), generic type parameters (`T`), dynamically typed classes and typing constructs (Python `Callable`, `Union`, `EndpointMetrics`), standard library runtime classes and constructors (ECMAScript `Date`, `Object`, `Math`, `Promise`, `Error`), built-in exceptions (`ValueError`), schema relations (SQL tables, CTEs, views, indexes), Terraform schema blocks, routine and method invocations (`printf()`, `.stream()`), symbolic operators (`+`, `-`, `*`, `/`, `=`, `==`, `<`, `>`, `?`, `:`), structural delimiters and brackets (`()`, `{}`, `[]`), upright code comments, and scope qualifiers (`context.`, `fmt.`, `std::`, `boost::`). Anchoring domain entities and routine call sites to the neutral canvas achieves optimal canvas tranquility ("Alabaster" effect) and eliminates the exhausting blue-and-grey zebra-striping of routine calls.
    - **Tier 2: Structural anchors (15–20% screen area) in Green, Yellow, Blue, and Violet**: Frames structural topology:
      - **Solarized Green**: Uses `#859900` for structural scaffolding and declarations (`package`, `func`, `fn`, `def`, `class`, `struct`, `interface`, `var`, `let`, `const`, `typedef`, `CREATE TABLE`, `DEFAULT`, `ASC`, `DESC`), reserved word operators (`sizeof`, `alignof`, `_Alignof`, `static_assert`, `_Generic`), and static primitive types and core built-in scalars (`int`, `double`, `u64`, `usize`, `bool`, `void`, SQL `VARCHAR` and `BIGINT`, Python built-in scalars `int`, `str`, `float`, `bool`, `bytes`, `list`, `dict`, `set`, `tuple`, `object`, `range`). Leveraging the human visual cortex's primary sensitivity to green hue provides effortless structural scanning without the "Primitive Fracture" or "Type Paradox" of conventional themes.
      - **Solarized Yellow**: Uses `#B58900` for uncontested control flow and jumps (`if`, `else`, `return`, `for`, `while`, `switch`, `case`, `select`, `defer`, `match`, `try`, `catch`, `throw`, `yield`, `await`, `CASE/WHEN`). Reserving Yellow exclusively for execution pathways ensures branch points and jump exits command instantaneous peripheral attention, completely uncontested by types, keywords, or document headings.
      - **Solarized Blue**: Uses `#268BD2` for routine and function declarations (`func New...`, `fn find...`, `def __init__`, `cleanup() {`), diff hunk headers (`@@ ... @@`), and Markdown H2 section boundaries.
      - **Solarized Violet**: Uses `#6C71C4` for the serene aspect layer, declarative metadata, annotations, decorators, attributes, imports, and modules (`@Service`, `@dataclass`, `#[derive]`, `[[nodiscard]]`, `import`, `from`, `use`, `package main`, `@module`, Markdown H3). Transforms stacked annotations into a quiet, elegant boundary that recedes behind the foreground code plane.

      - **Solarized Cyan**: Uses `#2AA198` for string literals, filesystem paths, unbroken escape sequences and format specifiers (`%s`, `\n`), raw backtick struct tags, and Markdown link targets.
      - **Solarized Magenta**: Uses `#D33682` for numeric literals, booleans (`true`, `false`), named `ALL_CAPS` and `iota` constants (`EXIT_FAILURE`, `MAX_BUFFER_SIZE`, `LevelDebug`), runtime environment global singletons (`console`, `process`, `globalThis`, `window`, `document`), regex literal bodies (`/^\/health[z]?$/`), and sentinel values (`nil`, `null`, `None`, `std::nullopt`, `_`, `this`, `self`).

  - **Two-tier configuration topology (the table versus key principle)**: In serialization and configuration languages like TOML, document section headers (`[table]`, `[[array]]`) represent macro-level structural boundaries and receive Solarized Blue (`#268BD2`) matching Markdown H2 and diff hunk headers. Enclosing brackets (`[`, `]`, `[[`, `]]`), dots (`.`), and equals signs (`=`) strictly remain in calm Base0 Grey (`#839496`), preventing visual flattening.

- **Pillar V: Pushdown automata state machine engineering**:

    - **Non-greedy transition eagerness**: Pushdown state transitions must match structural framing prefixes (such as Markdown list sigils `^\s*([-*+]|\d+\.)(?=\s)` or quote sigils `^\s*(>)`) and never greedily consume downstream content (`(.*)$`). Consuming downstream characters on transition starves child contexts, skipping inline formatting, code spans, and links.
    - **Opening delimiter consumption versus lookahead trap**: Context push rules must consume their opening delimiters (`match: '({{ident}})\s*(\()'` with capture 2 scoped to punctuation) rather than using lookaheads (`(?=\()`).     - **Positional and boundary anchoring**: In indentation-sensitive or statement-delimiter-free syntaxes (Python, YAML, Markdown), rules must enforce line-initial anchors (`^\s*`) and negative lookaheads (`(?!\s*[=:])`) to prevent statement block headers (`try:`, `finally:`) from poisoning expression contexts.

    - **Statement arm isolation**: Context-dependent statement blocks (such as shell `case ... in ... esac` arms) require dedicated pushdown contexts (`case-body`) to prevent line-initial pattern labels from being misparsed as command invocations in Blue.
    - **Contextual polysemy disambiguation**: Multi-purpose punctuation symbols (`*`, `@`, `#`) must be disambiguated by structural containment: SQL `*` in projection (`SELECT *`) versus binary arithmetic (`a * b` in Base0); shell `@` in parameter expansions (`$@` in Magenta) versus array subscripts (`${arr[@]}` in Cyan).
    - **Punctuation-safe word tokenization**: Plain-text fallback rules must segregate non-space runs into word runs (`` [^\s`*!_\[\]~()]+ ``), punctuation clusters, and fallback characters, preventing punctuation enclosures (`(**Debian or Ubuntu**,`) from swallowing adjacent markup delimiters.
    - **Multi-state grammar sequencing for tabular topology**: Pushdown automata must model tabular layouts as a multi-stage topological state machine (`table` to `table-after-header` to `table-body`) to distinguish Base1 headers from Base0 data cells.
    - **The lookaround guard protocol for contextual keywords**: Contextual keywords that double as identifier positions (such as ECMAScript `of`, `in`, `catch`, `finally`, `default`, Kotlin `value`, `data`, and `annotation` before `class` or `object` versus variable `value` and loop `in` versus containment `in`, and Swift `case` in enum variant declarations versus `switch` pattern arms) must be guarded by surrounding syntactic slots: negative lookbehinds `(?<!\.)` prevent chained method calls (`Array.of()`, `promise.catch()`) from triggering control flow Yellow, while lookaheads (`(?!\s*:)`, `(?=\s+(?:class|object)\b)`) disambiguate declaration sites from ordinary identifiers and expression operators.
    - **Computed member pushdown states**: State machines must push an autonomous expression context upon matching opening computed member brackets `\[` and pop on `\]`, delegating inner evaluation to the expression pipeline rather than greedily capturing bracketed spans as routine declarations.
    - **Lookahead key partitioning for dotted paths**: In serialization and configuration grammars (such as TOML), dotted key sequences (`pool.min_size`, `limits.per_minute`) must partition path segments using lookahead assertions `(?:\b[A-Za-z0-9_-]+\b)(?=\s*\.)` to cleanly distinguish dot accessors from value expressions without premature context popping or delimiter leakage.

- **Pillar VI: Tree-sitter AST query hierarchy and cascade engineering**:
  - **Core premise**: Neovim's Tree-sitter architecture evaluates declarative S-expression pattern queries over concrete syntax trees. Robust query design prevents AST shadowing and ensures polyglot injection:
    - **Root fallback invariance (the cascade principle)**: Root query capture groups (`@function.call = Base0`, `@function.builtin = Base0`, `@keyword.import = Violet`, `@variable.builtin = Magenta`) must strictly mirror the universal semantic contract. Contradictions in root highlights corrupt every embedded polyglot block and newly installed grammar. Aligning root captures enables hundreds of lines of repetitive per-language overrides to be pruned.
    - **Leaf-node dominance and priority predicates for compound sigils**: Parent container captures do not override child leaf nodes without explicit leaf captures or priority weighting (`#set! priority 120`). In compound AST nodes (such as Markdown alert callouts `[!NOTE]` or XML CDATA opening delimiters `<![CDATA[`), boundary leaf tokens (like brackets `[` and `]`) must be targeted directly with priority predicates (`(CDStart "[" @module (#set! priority 130))`) to prevent generic punctuation rules from fracturing compound enclosures.
    - **The transparent capture fallthrough trap (extmark attribute cascading)**: In Neovim's extmarks highlight engine, multiple Tree-sitter captures can attach to the same token range. If a higher-priority capture specifies `nil` for an attribute (such as `fg = nil` in `@none`), the renderer does not clear the attribute—it transparently falls through to the next capture in the stack that defines a value. Resetting an upstream-highlighted token to neutral canvas Base0 Grey (`#839496`) must never rely on `@none`; it requires binding the token to a concrete capture with an explicit Base0 Grey definition (such as `@markup.raw.block` for code blocks or `@variable`) reinforced by language-scoped overrides (`["@markup.raw.xml"] = { fg = colors.base0 }`).
    - **Autonomous language tree injection hygiene and runtimepath precedence**: Language injections instantiate autonomous `LanguageTree` child parsers that supersede and bypass all syntax rules of the host document. Injections must never match containers unconditionally (such as injecting JS into any element named `<script>`) without structural guards (such as `type="text/javascript"` attributes). Because base injection queries (`injections.scm`) do not concatenate with `;; extends`, the workstation orchestrator must guarantee user configuration (`~/.config/nvim/queries/`) maintains unconditional precedence at index 1 of Neovim's `runtimepath`.
    - **Query stream ordering**: In Tree-sitter query streams, broader generic captures occurring later silently supersede earlier specific captures unless guarded by priority assertions. Specialized domain rules (such as dunder attributes `__name__` or qualified receivers) must be defended with explicit precedence.
    - **Polyglot code block injection isolation**: Markdown code block injections dynamically invoke the target language's Tree-sitter parser, executing the full syntax contract of the embedded language with strict scope boundaries.
    - **Standard library class desensitization and global precedence**: Standard library runtime classes (`Date`, `Object`, `Math`, `Promise`, `Error`) must be prioritized to `@type` (Base0 Grey `#839496`) over upstream generic `@type.builtin` captures to prevent canvas fracture. Host runtime globals (`process`, `globalThis`) must be extended into `@variable.builtin` without excessive priority weighting that would override local function definitions (`function process()`).
    - **Base query supersedure for metadata elimination (the OSC 8 hyperlink trap)**: Tree-sitter query metadata (such as `(#set! @capture url ...)` in upstream HTML queries) attaches directly to extmarks during `query:iter_matches`. When present, Neovim's TUI emits OSC 8 terminal escape sequences (`\e]8;;<URL>\e\`), rendering tokens as clickable terminal hyperlinks in modern emulators like Ghostty. Because query metadata is collected cumulatively across all matching query files on `runtimepath`, setting a higher-priority highlight in `after/queries/` does NOT suppress metadata from upstream base queries. Eliminating rogue metadata requires superseding the base query directly in `~/.config/nvim/queries/<lang>/highlights.scm` without `;; extends`.
    - **Diagnostic underline isolation and hyperlink extmark suppression**: Diagnostics and document link providers in Neovim operate on an independent layer above syntax highlighting. Overriding `DiagnosticUnderline*` with `fg = "NONE"` ensures diagnostic severity is rendered exclusively as an undercurl or underline using `sp`, preserving syntax color fidelity.     - **Recursive AST query depth unrolling**: When Tree-sitter grammars (such as `tree-sitter-toml`) model dotted paths as nested binary trees (`(dotted_key (dotted_key (bare_key)) (bare_key))`), highlight queries must explicitly unroll pattern depths up to the grammar's depth limit. This ensures parent container semantics (`table` header Blue versus `pair` key Green) cascade down to all path segments without leaking into adjacent value expressions.
    - **Single-source-of-truth query architecture (base supersedure versus runtime extension)**: Neovim supports two query locations: `queries/<lang>/` (evaluated first, for base supersedure) and `after/queries/<lang>/` (evaluated last, with `;; extends` for additive rules). Conversely, when extending upstream distro queries additively (as in Go, Rust, Python, Bash, Kotlin, Swift), rules belong in `after/queries/<lang>/highlights.scm` with `;; extends`. Never maintain duplicate highlight queries across both directories for the same language: dual sets produce conflicting priority stacks and double AST traversal overhead.
    - **Document-order rule precedence and catch-all fallback sequencing**: In Tree-sitter query evaluation, rules at equal priority are evaluated sequentially in document order. When defining a fallback rule alongside specialized predicate captures (such as in Java Properties or JSON), generic catch-all patterns (`(value) @string`) must always precede specialized predicate rules (`((value) @number (#lua-match? ...))`). Placing catch-alls after specialized rules in document order causes the broader pattern to match downstream and overwrite specific syntax captures.

## 4. Step-by-step task recipes for agents

Follow these standard workflows when extending toolchains, CLI options, dotfiles, or documentation:

### Recipe A: Adding or updating a developer toolchain

1. Edit `.mise.toml` to declare the tool:
   - Use `"lts"` if the tool ecosystem supports LTS releases (such as `java = "lts"` and `node = "lts"`).
   - Use `"latest"` for all other stable tools (such as `go = "latest"`, `python = "latest"`, and `neovim = "latest"`).
2. If client CLI utilities are needed from distro package managers, add them to `modules/00-packages.sh`.
3. Update `.mise.toml` validation in `tests/test-system-setup.sh`.
4. Run `make test` and `make lint` to verify.

### Recipe B: Adding a setup CLI switch or option

1. Update `setup.sh` argument parser (`while [ $# -gt 0 ]; do ... done`).
2. Implement `--dry-run` and live behavior within the relevant `modules/<NN>-*.sh` script.
3. Add a test case in `tests/test-system-setup.sh` asserting both `--help` and `--dry-run` behavior.
4. Update the command-line options table in `README.md`.
5. Update `AGENTS.md` if the option establishes a new invariant.
6. Run `make test` and `make lint`.

### Recipe C: Adding a custom Git workflow or developer shortcut

1. Add the alias to `dotfiles/.aliases` (or function to `dotfiles/.zsh-functions` if multi-line).
2. Ensure no standard Oh-My-Zsh Git aliases are duplicated.
3. Add the alias or function name to the assertion list in `tests/test-zsh.zsh`.
4. Run `make test` and `make lint`.

### Recipe D: Modifying environment variables or `PATH`

1. Edit `dotfiles/.environment-variables`.
2. Ensure XDG paths (`XDG_DATA_HOME`, `XDG_CONFIG_HOME`, `XDG_CACHE_HOME`) are respected.
3. Update assertions in `tests/test-env.sh`.
4. Run `make test` and `make lint`.

### Recipe E: Adding a new managed dotfile

1. Drop the file or directory directly into `dotfiles/` (such as `dotfiles/.gitconfig` and `dotfiles/.tmux.conf`).
2. Dotfiles are automatically discovered and mirrored to `$HOME` by `modules/10-dotfiles.sh` and cleaned up by `modules/99-uninstall.sh`.
3. Add assertion to `tests/test-dotfiles.sh`.
4. Run `make test` and `make lint`.

### Recipe F: Adding a standalone CLI utility

1. Drop the executable script into `bin/` (such as `bin/my-util`).
2. Make it executable (`chmod +x bin/my-util`) and start with `#!/bin/bash` and `set -euo pipefail`.
3. It is automatically symlinked to `~/.local/bin/my-util` by `modules/20-bin.sh` and cleaned up by `modules/99-uninstall.sh`.
4. Add unit test to `tests/test-bin.sh`.
5. Run `make test` and `make lint`.

### Recipe G: Adding a new provisioning module

1. Create `modules/<NN>-<feature>.sh` (numbered between 00 and 99 by execution order).
2. Include standard shebang, `set -euo pipefail`, and source `lib/log.sh`, `lib/os.sh`, `lib/symlink.sh`.
3. Respect standard environment flags: `DRY_RUN`, `OS`, `ARCH`.
4. Wire the module into `setup.sh`.
5. Add test coverage and verify with `make test` and `make lint`.

### Recipe H: Documenting features and workspace keybindings

1. Identify the appropriate architectural tier in `README.md` (Mental model and geometry, Structural layers, Runtime engine and automation, or Toolchains and integrations).
2. Write concise, high-density prose explaining the intent, interactions, and mechanics (strictly eliminating marketing fluff, buzzwords, and conversational preambles).
3. If introducing or modifying keybindings, CLI flags, or shell commands, add or update the corresponding row in the dedicated reference table ([IDE workspace keybindings and navigation](README.md#ide-workspace-keybindings-and-navigation) or [Git and shell shortcuts](README.md#git-and-shell-shortcuts)).
4. Ensure all keys, flags, paths, and commands are enclosed in backticks (`Alt+h`, `--3pane`, `bin/ide`).
5. Review the surrounding section to prune outdated notes and preserve cohesive narrative rhythm.
6. Run `make lint` to verify Markdown formatting.

## 5. Anti-patterns and common traps

| Anti-pattern | Why it breaks | Correct implementation |
| :--- | :--- | :--- |
| Masking startup warnings (`2>/dev/null`) | Hides real syntax and configuration errors from the user. | Fix the root cause (trust configs via `mise trust`, install missing runtimes via `mise install`). |
| Hardcoding dotfile lists in scripts | Requires editing Bash arrays whenever dotfiles change. | Drop dotfiles in `dotfiles/`; let `modules/10-dotfiles.sh` auto-discover and mirror. |
| Inlining module logic into `setup.sh` | Re-creates a bloated, unmaintainable monolithic script. | Keep `setup.sh` strictly as an orchestrator CLI; place logic into `modules/<NN>-<name>.sh`. |
| Blind `ln -sfn` over existing directory | Creates a nested symlink (`~/.config/nvim/nvim`) instead of replacing the directory. | Use `lib/symlink.sh` (`link_dir` and `link_file`) which backs up physical directories to `.bak.<timestamp>`. |
| Hardcoding distro Neovim paths | Ubuntu 22.04 `apt` installs Neovim 0.9.5, which crashes modern LSP plugins. | Rely on modern Neovim provisioned via `mise` (`neovim = "latest"`). |
| Letting Go pollute `$HOME/go` | Clutters user home directory. | Export XDG variables: `GOPATH="$HOME/.local/share/go"` and `GOCACHE="$HOME/.cache/go-build"`. |
| Installing database daemons by default | Consumes system memory, starts unwanted background services, and opens local listening ports. | Install only client CLIs by default; require `--with-postgres`, `--with-mariadb`, or `--db <engine>` for server daemons. |
| Append-only feature documentation | Produces fragmented, 20-bullet flat lists with buried keybindings and broken narrative flow. | Restructure the section into the 4-tier hierarchy and index all keybindings in dedicated lookup tables. |
| Trapping shortcuts solely in paragraph prose | Users cannot quickly find keybindings when scanning documentation. | Always maintain dual representation: conceptual prose for architecture, tabular lookup for execution. |
| Polling `#(...)` scripts or cross-process state sync in `tmux` status bar | Spawns persistent subprocess forks on every timer tick, causes terminal micro-stutters and battery drain, leaves orphaned or stale status if processes exit unexpectedly, and duplicates prompt info. | Rely strictly on native zero-fork pure-C `tmux` format variables (`#{scroll_position}`, `#{pane_synchronized}`, `#{SSH_CONNECTION}`, `#{SSH_TTY}`, `#h`) and event-driven workspace options (`@ide_workdir`). |
| Screen-column link scraping under Markdown concealment | When `conceallevel > 0` or `render-markdown.nvim` conceals Markdown syntax, screen columns diverge from buffer byte columns, causing cursor-based link extractors to miss links or open the wrong target. | Traverse the Tree-sitter AST (`vim.treesitter.get_node({ ignore_injections = false })` for `inline_link` and `uri_autolink`, with `<cfile>` fallback), query `(atx_heading (inline) @h)` in the `markdown` tree for `#anchor` targets, and position mouse clicks via `<LeftMouse>` before extracting. |

## 7. Documentation architecture and technical writing style for agents

Technical documentation in this repository is engineered for cognitive efficiency, instant scannability, and long-term accuracy. It communicates system mental models and mechanical precision without marketing prose, conversational filler, or typographic clutter.

These guidelines synthesize the Google Developer Documentation Style Guide, Matthew Butterick's *Practical Typography*, Diátaxis, Google Engineering Practices, and Chris Beams' Git commit conventions. Any agent drafting, modifying, or refactoring documentation (`README.md`, `AGENTS.md`, PR descriptions, issues, comments, and commit messages) must adhere to the following 6 principles:

### Principle I: Intent-driven architecture (Diátaxis and macro-to-micro flow)

Separate documentation by reader intent rather than mixing tutorials, reference tables, and design history in a single stream:

- **Quick start (Tutorial)**: The shortest command sequence to reach a working state. Omit alternative flags, edge cases, and architectural history.
- **Task guides (How-to)**: Goal-oriented recipes written in the imperative mood for readers who already know the basics.
- **Lookup tables (Reference)**: Austere, factual tables and schemas that mirror the codebase without narrative prose.
- **Architecture (Explanation)**: System topology, design rationale, and trade-offs ("why"), organized from macro mental model down to runtime mechanics and concrete toolchains:
  - **Tier 1 (mental model and spatial architecture)**: System topology, geometry, layout, purpose, and visual metaphors (such as Inverted-T 3-pane versus 2-pane geometry and session isolation).
  - **Tier 2 (first-principles structural layers)**: Conceptual decoupling and behavioral tiers (such as the 4 keybinding layers: App-Local, Spatial Navigation, Editor and Explorer, Clickable Links and Clipboard).
  - **Tier 3 (runtime engines and automation)**: Execution mechanics, event loops, data flow, telemetry, and edge-case mitigation (such as native `autoread` and `checktime` synchronization and non-destructive pane parking).
  - **Tier 4 (toolchains, plugins, and integrations)**: Concrete tool configurations, LSP servers, syntax parsers, and terminal profile integrations.

### Principle II: Dual representation rule (prose and lookup tables)

- Interactive keybindings, CLI flags, environment variables, and shell shortcuts must never exist exclusively inside paragraph prose.
- Represent them in two places:
  - Conceptually within their structural section (explaining how they fit the workflow, why they are mapped, and how they avoid domain conflicts).
  - Tabularly in a dedicated reference table ([IDE workspace keybindings and navigation](README.md#ide-workspace-keybindings-and-navigation), [Git and shell shortcuts](README.md#git-and-shell-shortcuts)) with sentence-case column headers for fast lookup.
- Use tables only for genuine two-dimensional data (items sharing three or more attributes, or structured key-value lookups), never for single-column lists.

### Principle III: The non-accretion rule (holistic maintenance)

- When introducing or modifying features, never append a standalone bullet point or note to the end of an existing section.
- Review the surrounding section holistically:
  - Integrate the change into its proper architectural tier or table.
  - Prune superseded or redundant statements so the document reads as a single cohesive draft.

### Principle IV: High information density and zero fluff

- **No marketing or conversational filler**: Omit buzzwords ("effortlessly", "blazing fast", "seamlessly") and preambles ("Note that...", "In this section we will...", "It is worth mentioning...").
- **Concrete semantic payload**: Every sentence must state exact technical nouns, flags, file paths, key combinations, and deterministic runtime behaviors.
- **User-facing readability versus internal specification**: In `README.md`, communicate what features do and how to use them in clear, scannable prose. Never chain long sequences of inline code spans, internal variable or option names (`@ide_*`, `#{...}`), Tree-sitter S-expressions, URL route templates, or repetitive RGB hex codes in a single paragraph—keep low-level implementation mechanics in `AGENTS.md`.
- **Zero aspirational documentation**: Document only behavior that is implemented, tested, and verified against the current codebase.

### Principle V: Typography and formatting restraint (Google Style Guide, Butterick)

- **One format per span**: Never combine bold, italics, code font, or hyperlinks on the same text (no bolded code spans, no bolded links, no bold-italics, no bolded first-column table cells).
- **Strict role separation**:
  - **Code font**: Use backticks strictly for literal code, CLI commands, flags (`--3pane`), file paths (`dotfiles/.tmux.conf`, `init.lua`), configuration keys, and keyboard shortcuts (`Alt+h`, `Space e`, `Ctrl+Click`). Keep sentence punctuation outside the backticks.
  - **Bold**: Use `**...**` only for UI labels and run-in headings at the start of list items. Never use bold for mid-sentence emphasis or whole clauses.
  - **Italics**: Use `_..._` or `*...*` only when introducing or defining a term on first use, or for titles of standalone works.
- **Sentence case headings**: Use sentence case for all document titles, section headings, and table column headers (capitalize only the first word and proper nouns), with no trailing punctuation.
- **Zero yellow and zero artificial bold in headings**: Conforming to Section 1 invariants, never use yellow in Markdown headings and never apply bold font styles across entire headings (`bold = false`).
- **No decorative symbols or math arrows in prose**: Omit decorative emojis, GitHub emoji shortcodes, LaTeX math arrows (`$\rightarrow$`, `$\leftrightarrow$`), ASCII arrows (`->`, `<->`), and inequality signs (`>`) as prose connectors. Write plain verbs ("maps to", "takes precedence over") instead.
- **No horizontal section dividers**: Do not place horizontal rules (`---`) between sections; Markdown headings already provide structural hierarchy.
- **Clean punctuation**:
  - **Parentheses**: Use sparingly and keep short. Never place critical requirements inside parentheses, never nest parentheses, and never pack long lists of code spans inside parentheses mid-sentence. Avoid optional plurals like `file(s)`.
  - **Slashes**: Do not use slashes (`/`) in prose to join alternatives (write "or" or "and" instead of `read/write` or `and/or`). Reserve `/` for file paths, URLs, and literal commands.
  - **Dashes**: Use hyphens (`-`) for compound modifiers, "to" for ranges, and unspaced em-dashes (`—`) sparingly for clause breaks. Never use dashes to separate a list term from its definition; use a colon after run-in list headings.
- **List discipline**:
  - Use numbered lists strictly for sequential steps where order matters; use bulleted lists for non-sequential sets.
  - Keep list items parallel in grammatical structure and consistent in terminal punctuation.
  - Avoid italic parenthetical asides like `*(Note: ...)*`. If a detail matters, state it as a normal sentence; reserve callout blocks (`> [!IMPORTANT]`) for destructive hazards or critical prerequisites.

### Principle VI: Surface-specific standards

- **READMEs**:
  - Open with a concise two-to-three sentence summary of what the tool does and which platforms it targets.
  - Follow immediately with a minimal quick-start block, then task guides, reference tables, and troubleshooting.
  - Keep developer internals, build pipeline mechanics, and agent instructions out of user-facing READMEs.
- **Pull request descriptions (Google CL Description Guide)**:
  - **Title**: A standalone imperative sentence summarizing the change.
  - **Summary ("why" before "what")**: Explain the problem or limitation in the prior code and why this design was chosen. Group changes by subsystem or behavior rather than repeating the line-by-line diff.
  - **Lean templates**: Keep PR templates to `## Summary` and `## Verification` with plain-text checkboxes and zero decorative emojis.
- **Issues**:
  - **Bug reports**: Include four factual sections: environment, numbered steps to reproduce, expected behavior, and actual behavior (with exact terminal output in a fenced code block).
  - **Feature proposals**: State the workflow problem or use case before proposing a CLI or schema design.
- **Code and review comments**:
  - **Doc comments**: Exported functions and modules must state their contract and error behavior in complete sentences.
  - **Implementation comments**: Explain why a non-obvious constraint or workaround exists, never what the code literally does.
  - **Review comments**: Critique the code rather than the author, explain the underlying engineering principle, and prefix non-blocking polish suggestions with `Nit:`.
- **Commit messages (Chris Beams' 7 Rules)**:
  - **Subject line**: Imperative mood ("If applied, this commit will..."), capitalized, no trailing period, targeting 50 characters (hard cap at 72).
  - **Blank line**: Separate the subject from the body with a single blank line.
  - **Body**: Wrap at 72 characters in plain text (avoid heavy Markdown formatting in commit bodies). Explain what problem existed and why the change was made, placing issue references in trailers at the bottom.
